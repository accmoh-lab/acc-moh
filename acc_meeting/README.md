# acc_meeting — إدارة الاجتماعات ومتابعة المهام (Odoo 19)

وحدة Odoo مخصصة لإدارة دورة الاجتماع كاملة: الجدولة، الأجندة، تقرير التحضير، المحضر، القرارات، توزيع المهام، المتابعة في الاجتماع التالي، وترحيل البنود للمستويات الأعلى.

> **حالة الوحدة:** كُتبت وفق معايير Odoo 19، وفُحصت صياغة Python وXML برمجيًا فقط.
> لم يُشغَّل Odoo في بيئة التطوير، لذلك **لم تُجرَّب الوحدة فعليًا بعد**، ولم تُشغَّل الاختبارات المرفقة.
> يجب تثبيتها على بيئة Staging وتشغيل الاختبارات قبل أي استخدام على بيانات حقيقية.
>
> **قيد المنصة:** الوحدة تحتاج **Odoo.sh أو On-premise**. لا يمكن تركيبها على Odoo Online.

## مستويات الاجتماعات

| المستوى | يرتبط بـ | مستوى الصلاحية (Authority Level) |
|---|---|---|
| اجتماع قسم (Department) | قسم من أقسام الشركة (`hr.department`) | 10 |
| اجتماع وحدة نشاط (Business Unit) | وحدة نشاط (`acc.business.unit`، تُعرَّف من Configuration) | 20 |
| اجتماع مجلس الإدارة (Board) | لا يرتبط بقسم أو وحدة | 30 |

يمكن إضافة أنواع أخرى من Configuration ← Meeting Types. الترحيل يكون دائمًا إلى مستوى أعلى.

## من يرى ماذا

| الدور | الصلاحية |
|---|---|
| **قائد الاجتماع** (المنظِّم، رئيس الاجتماع، مسجّل المحضر) | يعدّل الاجتماع كاملًا: الأجندة، الحضور، تقرير التحضير، المحضر، القرارات، المهام، ويغلق الاجتماع. |
| **عضو (حاضر)** | يرى اجتماعاته فقط، وأجندتها، وتقرير التحضير بعد إتاحته، وتقرير الاجتماع بعد إغلاقه. لا يعدّل الاجتماع. |
| **مسؤول عن مهمة** (غير حاضر) | يرى الاجتماع الذي نشأت منه مهمته، ويحدّث حالة مهمته. لا يرى تقرير التحضير. |
| **Meetings: Manager** | يرى كل الاجتماعات ويدير الإعدادات والتقارير. |
| مدير النظام (Administrator) | يحصل تلقائيًا على صلاحية Manager. |

المستخدمون الآخرون يُسند لهم الدور **Meetings: User** يدويًا من إعدادات المستخدم.

**حدود يجب معرفتها:**
- المسؤول عن المهمة يستطيع تعديل حقول مهمته، وليس الحالة فقط. التقييد على مستوى الحقل يحتاج تطويرًا إضافيًا.
- الحضور لا يكتبون في Chatter الاجتماع (يلزم صلاحية كتابة). التعليقات تتم على المهام.
- الأجندة تظهر للحضور فور تأكيد الاجتماع. الذي يُحجب حتى قبل الاجتماع بـ48 ساعة هو **تقرير التحضير** فقط. هذا افتراض يمكن تغييره.

## دورة العمل

1. **الجدولة:** إنشاء الاجتماع، اختيار النوع والقسم أو وحدة النشاط، الموعد، المكان، والحضور.
2. **الأجندة:** يسجلها القائد. عند «Confirm & Send Invitations» تُرسل دعوات Calendar، وتُحمَّل تلقائيًا بنود المتابعة السابقة والبنود المرحّلة لهذا المستوى.
3. **التحضير:** لكل اجتماع تقرير تحضير واحد يكتبه القائد: خلفية الموضوع، القرارات المتوقعة، المطلوب من الأعضاء. يضغط «Publish to Attendees».
   - يظهر التقرير للحضور عندما يكون **منشورًا** و**قبل الاجتماع بـ48 ساعة أو أقل**.
   - الساعات الافتراضية 48، وتُغيَّر من System Parameters: `acc_meeting.prep_release_hours`.
   - إجراء مجدول كل 15 دقيقة يتولى الإتاحة، ويرسل إشعارًا للحضور. ويرسل تذكيرًا (Activity) للقائد إذا دخل الاجتماع نافذة الـ48 ساعة وتقرير التحضير لم يُنشر.
   - إذا نُشر التقرير داخل النافذة فهو يتاح فورًا. بعد إتاحته لا يمكن سحبه.
4. **الاجتماع:** «Start Meeting».
5. **بعد الاجتماع:** يسجل القائد المحضر (Minutes)، والقرارات (Decisions) بنتيجة كل منها: معتمد / مرفوض / مؤجَّل / للعلم، وبنود المتابعة (Action Items) لكل منها مسؤول وموعد. لا يُغلق الاجتماع بدون محضر. عند «Close Meeting» تظهر لكل مسؤول مهمته في Activities.
6. **الاجتماع التالي:** «Schedule Next Meeting». تظهر تلقائيًا مهام الاجتماع السابق في تبويب *Previous Actions Review*، ولكل مهمة نتيجة: **Completed / In Progress / Delayed / Cancelled**.
   - عند Delayed أو Cancelled يلزم **سبب الانحراف**، وعند Delayed يلزم **موعد جديد**.
   - عند إغلاق الاجتماع تُطبَّق النتائج على المهام، ويُسجَّل التأجيل وعدد مرات التأجيل.
7. **الترحيل:** زر **Escalate** على المهمة يرحّلها إلى مستوى أعلى (مثلًا من قسم إلى وحدة نشاط أو إلى Board) مع السبب. تظهر في أجندة اجتماع ذلك المستوى.

## التقارير

- **Meeting Reports:** الاجتماعات المغلقة. الزر Print يعطي محضرًا بصيغة PDF: الحضور، تقرير التحضير، الأجندة، مراجعة البنود السابقة، المحضر، القرارات، والمهام الجديدة.
- **Preparation Reports:** تقارير التحضير المتاحة للمستخدم.
- **Dashboard:** الأداء حسب القسم، البنود المتأخرة، البنود المرحّلة لـBoard والإدارة العليا، الإنجاز حسب نوع الاجتماع.
- **Deviation Analysis:** تحليل الانحرافات حسب السبب والقسم والمسؤول ونوع الاجتماع.
- **تنبيه تلقائي:** تذكير للمسؤول بالمهام المتأخرة كل 3 أيام تقريبًا.

## التثبيت على Odoo.sh

1. أضف المجلد `acc_meeting` إلى مستودع Git المرتبط بمشروع Odoo.sh.
2. ادفعه إلى **فرع Staging** أولًا، وليس إلى Production.
3. من Apps: Update Apps List ثم ثبّت **ACC Meetings & Action Follow-up**. يثبّت معه `hr` و`calendar` إن لم يكونا مثبتين.
4. أضف وحدات النشاط من Configuration ← Business Units، وأسند المجموعات للمستخدمين.
5. شغّل الاختبارات: `odoo-bin -d <db> -i acc_meeting --test-tags /acc_meeting --stop-after-init`
6. جرّب بمستخدمين حقيقيين: قائد، عضو، مسؤول مهمة غير حاضر، وشخص خارج الاجتماع.
7. بعد نجاح التجربة على قسم واحد (Pilot)، ادمج في Production.

## المتطلبات

- Odoo 19.0 على Odoo.sh أو On-premise.
- الوحدات: `base`, `mail`, `calendar`, `hr`. القسم يؤخذ من سجل الموظف المرتبط بالمستخدم المسؤول.

## بنية الوحدة

| النموذج | الوظيفة |
|---|---|
| `acc.meeting` | الاجتماع: الجدولة، الأجندة، المحضر، الربط بالاجتماع السابق والتالي |
| `acc.meeting.type` | أنواع الاجتماعات، والمستوى (`scope`)، ومستوى الصلاحية (`level`) |
| `acc.business.unit` | وحدات النشاط |
| `acc.meeting.attendee` | الحضور وحالة الحضور |
| `acc.meeting.agenda` | بنود الأجندة |
| `acc.meeting.preparation` | تقرير التحضير وإتاحته للحضور |
| `acc.meeting.decision` | قرارات الاجتماع |
| `acc.meeting.task` | المهمة أو المشكلة، مع المسؤول والموعد والترحيل |
| `acc.meeting.followup` | مراجعة المهام السابقة وسبب كل انحراف (مصدر تقرير الانحرافات) |
| `acc.meeting.deviation.reason` | قائمة أسباب الانحراف القابلة للتعديل |

## الترجمة العربية

ملف `i18n/ar.po` يغطي الواجهة والرسائل والقوائم. أُنتج بسكربت، ولم يُجرَّب داخل Odoo.
إذا ظهر نص بالإنجليزية فمعناه أن المرجع في الملف لا يطابق النص. يُصحَّح بتصدير الترجمة من Odoo (Settings ← Translations ← Export) ثم الدمج.

## تطوير لاحق مقترح

- إضافة أعضاء القسم تلقائيًا كحضور عند اختيار القسم.
- تقييد المسؤول عن المهمة بتحديث الحالة فقط.
- صفحة Dashboard واحدة بمؤشرات (KPIs) مجمعة.
- ربط بنود المتابعة بـ`project.task` إذا اعتمدتم Project مسارًا موحدًا للمهام.
