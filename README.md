# acc_meeting — إدارة الاجتماعات ومتابعة المهام (Odoo 19)

وحدة Odoo مخصصة لإدارة دورة الاجتماع كاملة: الجدولة، الأجندة، المحضر، توزيع المهام، المتابعة في الاجتماع التالي، وترحيل البنود للإدارات الأعلى و Board.

> **حالة الوحدة:** كُتبت وفق معايير Odoo 19، وتم فحص صياغة Python وXML برمجيًا.
> لم يُشغَّل Odoo في بيئة التطوير، لذلك **لم تُجرَّب الوحدة فعليًا بعد**. يجب تثبيتها على بيئة Staging وتشغيل الاختبارات المرفقة قبل أي استخدام على بيانات حقيقية.

## دورة العمل

1. **الجدولة:** إنشاء الاجتماع، اختيار النوع (Department / Management / Executive / Board)، الموعد، المكان، الحضور.
2. **الأجندة:** تسجيل بنود الاجتماع قبل موعده. عند الضغط على «Confirm & Send Invitations» تُرسل دعوات Calendar للحضور.
3. **التنفيذ:** «Start Meeting» ثم تسجيل المحضر (Minutes) والمهام والقرارات والمشاكل في تبويب Action Items، لكل بند مسؤول وموعد استحقاق.
4. **الإغلاق:** «Close Meeting». يظهر لكل مسؤول نشاط (Activity) بمهمته في Odoo.
5. **الاجتماع التالي:** «Schedule Next Meeting» ينشئ الاجتماع التالي، ويعرض تلقائيًا في تبويب *Previous Actions Review* كل مهام الاجتماع السابق، مع المهام المفتوحة من اجتماعات أقدم.
   لكل مهمة تُحدَّد النتيجة: **Completed / In Progress / Delayed / Cancelled**.
   - عند **Delayed** أو **Cancelled** يلزم اختيار **سبب الانحراف**، وعند Delayed يلزم **موعد جديد**.
   - عند إغلاق الاجتماع تُطبَّق النتائج على المهام (تغيير الحالة، الموعد الجديد، عدد مرات التأجيل، وتسجيل السبب في سجل المهمة).
6. **الترحيل (Escalation):** زر **Escalate** على المهمة يرحّلها إلى مستوى أعلى (مثل Board) مع سبب الترحيل. تظهر تلقائيًا في أجندة اجتماع ذلك المستوى القادم.
   لا يمكن الترحيل إلا إلى مستوى أعلى من المستوى الحالي.

## التقارير والمتابعة

- **Deviation Analysis:** تحليل الانحرافات حسب السبب والمسؤول ونوع الاجتماع.
- **Action Items:** عرض List / Kanban / Pivot / Graph، مع فلاتر Overdue و Escalated و Postponed.
- **تنبيه تلقائي (Cron):** تذكير للمسؤول بالمهام المتأخرة كل 3 أيام تقريبًا.

## الصلاحيات

| المجموعة | الصلاحية |
|---|---|
| **Meetings: User** | يرى الاجتماعات التي ينظمها أو يحضرها، والمهام المسندة إليه أو التي أنشأها أو المرتبطة باجتماعاته. يحدّث حالة مهامه. |
| **Meetings: Manager** | يرى كل شيء، وينظم الاجتماعات، ويدير الإعدادات والتقارير. |

مدير النظام (Administrator) يحصل تلقائيًا على صلاحية Manager. باقي المستخدمين تُسند لهم المجموعة يدويًا.

## التثبيت على Odoo.sh

1. أضف المجلد `acc_meeting` إلى مستودع Git المرتبط بمشروع Odoo.sh (في جذر المستودع أو داخل مجلد addons).
2. ادفعه إلى **فرع Staging** أولًا، وليس إلى Production.
3. من Apps: Update Apps List ثم ثبّت **ACC Meetings & Action Follow-up**.
4. أسند المجموعات للمستخدمين، وراجع **Configuration ← Meeting Types** و **Deviation Reasons**.
5. شغّل الاختبارات: `odoo-bin -d <db> -i acc_meeting --test-tags /acc_meeting --stop-after-init`
6. بعد نجاح التجربة على إدارة واحدة (Pilot)، ادمج في Production.

## المتطلبات

- Odoo 19.0 على Odoo.sh أو On-premise (Odoo Online لا يدعم الوحدات المخصصة).
- الوحدات: `base`, `mail`, `calendar`.

## بنية الوحدة

| النموذج | الوظيفة |
|---|---|
| `acc.meeting` | الاجتماع: الجدولة، الأجندة، المحضر، الربط بالاجتماع السابق والتالي |
| `acc.meeting.type` | أنواع الاجتماعات ومستوى الصلاحية (Authority Level) |
| `acc.meeting.attendee` | الحضور وحالة الحضور |
| `acc.meeting.agenda` | بنود الأجندة |
| `acc.meeting.task` | المهمة / القرار / المشكلة، مع المسؤول والموعد والترحيل |
| `acc.meeting.followup` | مراجعة المهام السابقة وسبب كل انحراف (مصدر تقرير الانحرافات) |
| `acc.meeting.deviation.reason` | قائمة أسباب الانحراف القابلة للتعديل |

## تطوير لاحق مقترح

- ربط الأقسام (`hr`) لعرض الأداء حسب الإدارة.
- Dashboard لـ Board بمؤشرات (KPIs) جاهزة.
- محضر الاجتماع بصيغة PDF موحدة.
- ترجمة الواجهة للعربية (`i18n/ar.po`).
- تفريغ الاجتماعات تلقائيًا (Fireflies / Teams) وإدخال المهام.
